# iio: ONEXPLAYER 3 IMU (ACPI 10EC5280) is a BMI260 but binds bmi160_i2c and fails with -121 - no gyro/accel device

**Kernel:** 7.2.0-valve1-1-neptune-72 (SteamOS 3.10). **Device:** ONE-NETBOOK ONEXPLAYER 3, BIOS 5.09.

```
bmi160_i2c i2c-10EC5280:00: supply vdd not found, using dummy regulator
bmi160_i2c i2c-10EC5280:00: supply vddio not found, using dummy regulator
bmi160_i2c i2c-10EC5280:00: mounting matrix not found: using identity...
bmi160_i2c i2c-10EC5280:00: Error reading chip id
bmi160_i2c i2c-10EC5280:00: probe with driver bmi160_i2c failed with error -121
```
No `/sys/bus/iio/devices/iio:device*` is created, so no motion controls are available to InputPlumber/HHD/Steam.

**Findings:** the device sits on I2C bus 2 at address 0x68 (100 kHz). Reading the chip id register directly with `i2cget` returns 0x27, which is a Bosch BMI260. `bmi160_i2c` claims the ACPI id 10EC5280 and fails; `bmi270_i2c` supports the BMI260 but only matches the ACPI ids BMI0160 and BMI0260. An ACPI table upgrade that renames the node to BMI0260 makes the chip probe and deliver data, so adding the 10EC5280 id to `bmi270_i2c` (a platform quirk) would fix detection without a table override.
